Hana ID smoke test

Local test tooling (not a partner integration guide) that logs in through the Hana vault (@hana-id/web): the vault iframe, the Hana login popup, Google and POST /v1/login. Keys and Google tokens stay in the Hana pages; this page only sees addresses, status and (pk_test_ apps) per-stage timings. The direct page runs the old in-page flow (Google, openid only → /v1/sessions → /v1/derive) for the split-flow baseline and the replay tests.

2. Wallet

Addresses use derivation v1 (@hana-id/core/derivation), computed in the vault. Testnet addresses are disposable until the address freeze.

3. Signing and auto-approve

Every request is signed only, never broadcast. Set the demo policy with pnpm --filter @hana-id/scripts admin <env> app:settings <app> --auto-approve apps/smoke/policies/demo-auto-approve.json --remote from the repo root (a relative path is resolved against the directory you ran pnpm from); it takes effect after the env's change delay.
