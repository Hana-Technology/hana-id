Google email scope spike (email login build plan batch 0)

Local only: no Hana API, no chain. Tokens are decoded in this page; the access token goes only to Google (tokeninfo by POST, userinfo; never revoked, as production since D265: revoking ends the whole grant, so Google would ask again at every login). Nothing personal reaches the summary: no address, no sub, no token. The on-chain ID token must stay openid-only (D25). A and B compare one request (response_type=id_token token, scope=openid email) with the fallback (a second, silent response_type=token, scope=email request); C and D check B's grant afterwards. E is the flow decided in D270 (GOOGLE_EMAIL_FLOW = 'token_first' in packages/web/src/auth/google.ts): an email access token first (response_type=token, scope=openid email), its sub from tokeninfo, then a silent response_type=id_token, scope=openid, prompt=none request for that account; E2 repeats only that silent request, as a returning user's login. Legs C and E must pass before the switch. Run it with a personal Gmail account, a Workspace account on its own domain (hd), and a Google account registered with an outside address; note what the consent screen lists each time.
